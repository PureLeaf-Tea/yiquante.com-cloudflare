# 懿泉茶业 YiQuanTea.com — 云服务账号与密钥管理规范

> **版本**: v1.0 | **日期**: 2026-08-11
>
> **本文档定位**：记录所有云服务的账号信息、负责人、交接流程，避免"只有一个人知道密码、离职后账号失联"。
> **阅读对象**：公司管理层 + 技术负责人。
>
> ⚠️ 本文档包含敏感信息（账号列表），请妥善保管，不要外传。

---

## 一、核心原则

1. **双人知晓**：每个云服务账号至少两个人知道登录方式（主负责人 + 备用联系人）
2. **统一存储**：所有密钥统一存在公司的加密文档里（推荐 1Password 或加密 Excel）
3. **交接必走**：任何负责人变动，必须先完成账号交接再离职
4. **不硬编码**：密钥绝不写在代码里，只通过环境变量 `.env` 注入

## 四、交接流程

### 4.1 正常交接（人员离职/调岗）

1. **提前通知**：至少提前 2 周告知技术负责人
2. **逐步移交**：按上面账号清单逐项移交
   - 新负责人注册对应服务的账号（如需要）
   - 主负责人将新负责人添加为协作者/子账号
   - 确认新负责人能正常登录和操作
3. **密钥更新**：交接完成后，更新可能被前负责人知晓的密钥（如 API Token）
4. **文档更新**：更新本文档的负责人信息

### 4.2 紧急接管（突然失联）

如果主负责人突然联系不上：

1. 备用联系人用自己的账号登录对应服务
2. 如果备用联系人是协作者，可以直接操作
3. 如果不是，通过"忘记密码"找回（前提：注册邮箱公司可控）
4. 找回后立即重置密钥
5. **教训**：说明之前没有做好"双人知晓"，事后必须补齐

## 五、定期检查清单

每季度（3 个月）检查一次：

- [ ] 所有账号都能正常登录
- [ ] 所有密钥都未过期
- [ ] 域名续费状态正常（距到期 > 60 天）
- [ ] 双人规则仍然有效（每个账号至少 2 人知晓）
- [ ] 负责人名单更新（有变动吗？）
