## 1. 项目定位（一句话）

主站 yiquantea.com 的新模块：**员工在后台创建客户订单，通过微信把订单链接发给客户，客户点开（或扫码）在手机上看自己的订单**；订单里的商品图片、商品详情页**与主站共用**。

## 4. 前台页面规格

### 4.1 客户订单页 `/o/[orderNo]`（新增，公开，无需登录）

**用途**：员工通过微信把链接发给客户，客户点开（或扫二维码）直接看自己的订单。

**路由规则**：根级路由，**不放在 [locale] 下**（客户直达不经过语言切换；页面语言由订单 `lang` 字段决定）。

**展示内容**（继承 v1.0 订单页结构 + 主站视觉）：
1. 顶部 header：品牌「懿泉茶业 / YiQuanTea」+ 订单状态徽标（待发货 PENDING / 已发货 SHIPPED）；
2. 客户信息：姓名、订单号、日期；
3. 「您购买的商品」区块：每件商品带缩略图（小图）、商品名（当前语言）+ 英文名 · 规格 + 数量；**整行可点击** → 跳转该商品详情页（见 4.2）；
4. 「您的赠品」区块：绿色徽标 + 赠品列表（同样来自图库，可点击看详情）；
5. 祝福语：外文 + 中文两行；
6. 底部：联系方式（tea.yiquantea@gmail.com，或主站配置的邮箱 yqtea.cn@gmail.com，以主站 site 配置为准）。

**主题切换（新增）**：
- 两种主题：①「主站品牌色」深绿 `#1a3a1a` + 暖金 `#c9aa7b` + 奶油白 `#fdfbf7`（**默认**）；②「深咖暖色」深咖 `#4A2C2A` + 金 `#B8860B` + 米白 `#FBF7F0`（沿用原订单模板）。
- 粒度：**全局默认主题 + 每个订单可单独覆盖**（后台设置，见 5.2）。

**语言规则**：整页界面文字与商品名称/介绍，全部按订单 `lang` 字段语言显示；缺失回退见第 7 节。

**OG 社交分享标签（新增，重要）**：见第 8 节。订单页被分享到微信/WhatsApp/Telegram/Facebook 时，需显示友好卡片。

**空状态**：订单不存在 → 显示「订单不存在或链接有误」。

### 4.2 商品详情页（复用主站 `/zh/products/[slug]` 等，含订单场景优化）

**用途**：客户点订单里的商品后查看。**复用主站商品详情页**（多图轮播、六语言描述、冲泡指南、推荐产品等已具备）。

**订单场景优化（新增）**：
- 从订单页跳转详情页时，URL 带来源参数（如 `?from=order&lang=xx`）；
- **隐藏价格 / 询价 / 推荐产品** 等电商元素，仅保留商品介绍（默认行为）；
- 是否隐藏由**后台员工控制**（见 5.1 商品增强：每商品可设"订单详情是否显示价格/询价"开关，默认隐藏；也可设全局默认）。
- 语言：订单跳转时按订单 `lang` 定位到对应 locale 的详情页（如俄语订单 → `/ru/products/slug`）。

**详情页自适应模板（新增，重点）**：详情页内容模块采用「**数据驱动自动显隐**」——每个模块（大图、名称、规格、产地、工艺、冲泡、整体介绍等）**有数据就显示、没数据自动隐藏**。员工不用为了模板好看硬填所有字段（"有多少料穿多少衣"）。主站现有的「拖拽布局」功能保留为**可选高级功能**，自动显隐兜底、拖拽锦上添花。

**产地/工艺/冲泡字段（独立字段，多语言）**：产地（origin）、工艺（process）、冲泡（brewingGuide）、整体介绍（description）**各为独立字段、独立模块**，按字段有无内容自动显示/隐藏：

| 商品类型 | 产地 | 工艺 | 冲泡 | 整体介绍 |
|---|---|---|---|---|
| 茶叶类（金骏眉等） | ✅有则显示 | ✅有则显示 | ✅有则显示 | ✅有则显示 |
| 包装容器类（合金罐等） | ❌空→隐藏 | ❌空→隐藏 | ❌空→隐藏 | ✅显示 |
| 赠品类（紫砂雕塑等） | ❌空→隐藏 | ❌空→隐藏 | ❌空→隐藏 | ✅显示 |

字段实现：在 `product_translations` 表新增 `origin`（产地）、`process`（工艺）两个多语言文本字段；冲泡复用现有 `brewingGuide`、介绍复用现有 `description`（六语言，见 6.4）。

### 4.3 首页订单卡片墙（后台内，需登录）

**用途**：公司内部总览所有订单。放在后台体系内（登录后可见，非公开）。

- 卡片内容：客户姓名、订单号、日期、状态徽标、首件商品缩略图、订单语言标识；
- 交互：点卡片 → 新窗口打开客户前台订单页 /o/[orderNo]（检查客户实际看到的效果）；
- 支持按状态筛选（全部/待发货/已发货）、按客户姓名/订单号搜索；
- 入口：后台新增「订单管理」菜单即为该卡片墙（列表/卡片两种视图）。

## 5. 后台功能规格

### 5.1 商品管理增强（在现有 /admin/products 基础上加开关 + 产地工艺字段）

现有产品管理已支持：增删改、多图、多语言翻译、详情页布局、上架/下架（status）。**新增两个开关 + 产地/工艺字段**：

1. **「官网前台显示」开关**（新增，字段建议 `showOnStorefront`，默认 true）：
   - 关闭后，该商品**不在官网前台**（产品列表/搜索/推荐）出现；
   - 但**订单创建时仍可选用**（赠品、包装罐、紫砂雕塑等非售卖品用此开关隐藏于前台）。
   - 员工可自由决定哪些商品上官网前台、哪些不上。
   - 与现有 `status`（上架/下架）区分：`status=inactive` 是整体停用；`showOnStorefront=false` 是"仅订单可见、前台隐藏"。

2. **「订单详情页显示价格/询价」开关**（新增，字段建议 `showPriceInOrder`，默认 false）：
   - 决定从订单跳转详情页时，是否显示价格、询价、推荐产品等电商元素；
   - 默认关闭（隐藏），员工可对个别商品打开。

3. **产地/工艺/冲泡/介绍字段（新增，多语言）**：
   - 商品编辑页新增「产地」「工艺」两个多语言输入框（六语言，可留空）；冲泡、整体介绍复用现有的冲泡指南、描述字段；
   - 这些字段**可留空**，详情页按「有数据就显示、没数据自动隐藏」自动适配（见 4.2 自适应模板）；
   - 商品图片、规格、名称等其他字段照旧。

### 5.2 订单管理 `/admin/orders`（新增菜单）

**核心流程：选客户 → 从图库点选商品与赠品 → 填数量 → 设语言/状态/主题 → 保存，前台 /o/订单号 自动生效。**

1. **订单列表（卡片墙）**：见 4.3；支持筛选、搜索；行内可切换状态。
2. **新建/编辑订单**表单字段：
   - 客户：下拉选择（从客户名单选；**选中自动带出该客户默认语言**，可改）；
   - 订单号：自动生成（`YQ-日期-客户缩写-序号`，如 `YQ-20260828-JC01`）或手动输入；
   - 日期：默认今天，可改；
   - 语言：下拉（六语言 zh/en/ru/de/es/fr），默认取客户默认语言；
   - 主题：下拉（「主站品牌色」默认 / 「深咖暖色」），默认全局设置，可单订覆盖；
   - 商品清单：**从商品图库点选添加**（弹层按分类筛选、可搜索，点击添加；每件填数量；可删除）；**注意：可选到 `showOnStorefront=false` 的商品**（订单专用）；
   - 赠品清单：同样从图库点选（按"赠品/摆件"等分类筛），填数量；
   - 祝福语：外文 + 中文两栏（提供默认文案，可改）；
   - 状态：待发货 / 已发货；
   - 备注：仅后台可见。
3. **删除订单**：二次确认。
4. **二维码**：订单详情内「查看二维码」弹窗，展示前台链接 `https://yiquantea.com/o/[orderNo]` 的二维码（白底深色码、留白充足），可打印/截图；同时提供「复制链接」按钮（员工微信粘贴发送）。

### 5.3 客户名单 `/admin/customers`（新增菜单）

1. 客户列表：姓名、国家、默认语言、备注、创建时间；
2. 新建/编辑：姓名（必填）、国家（自由文本或下拉）、默认语言（六语言下拉）、备注；
3. 删除：被订单引用时二次确认（订单保留，仅显示"客户已删除"）。

## 6. 数据模型（进主站 Neon PostgreSQL，Drizzle schema 新增/增强）

> 在 `drizzle/schema/` 新增 `customers.ts`、`orders.ts`；在 `products.ts` 的 `products` 表加两个布尔字段、`product_translations` 表加两个文本字段（origin/process）。**用 drizzle-kit generate 生成迁移，migrate 执行**，走主站现有迁移体系。

### 6.1 新增表 `customers`（客户）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | 默认随机 |
| name | varchar | 姓名（必填） |
| country | varchar | 国家，可空 |
| defaultLang | varchar | 默认语言代码（en/zh/ru/de/es/fr），默认 en |

### 6.2 新增表 `orders`（订单）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | 默认随机 |
| orderNo | varchar UNIQUE | 订单号（如 YQ-20260828-JC01） |
| customerId | uuid FK → customers.id | 客户（可空，客户删除后置 null） |
| date | varchar / date | 订单日期 YYYY-MM-DD |
| status | varchar | pending 待发货 / shipped 已发货 |
| lang | varchar | 订单显示语言代码，默认 en |
| theme | varchar | 主题：brand（主站品牌色）/ classic（深咖暖色），默认 brand |
| blessingForeign | text | 外文祝福语 |
| blessingCn | text | 中文祝福语 |

### 6.3 新增表 `order_items`（订单明细）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid PK | 默认随机 |
| orderId | uuid FK → orders.id（onDelete cascade） | 所属订单 |

### 6.4 增强 `products` 表 + `product_translations` 表

`products` 表加两个布尔字段：

| process | text | 工艺（多语言，空则详情页"工艺"模块自动隐藏） |

## 7. 多语言机制（复用主站）

- **界面文字**：复用主站 messages/ 六语言字典；订单页新增的文案键（如"您的订单""赠品"等）并入字典。
- **商品内容**：复用 `product_translations`（按 locale 存 description + brewingGuide），六语言。
- **订单语言**：订单 `lang` 字段决定订单页显示语言；`/o/[orderNo]` 无 locale 前缀，页面内按 lang 渲染（可用 next-intl 的按请求指定 locale 能力）。
- **回退规则**：某语言缺失 → 回退 en → 再回退 zh，绝不空白。
- **商品详情页跳转语言**：订单跳转详情页时，用订单 lang 对应 locale 的 URL（如 `?from=order`）。

## 8. OG 社交分享标签（新增，重点）

**目标**：订单页、商品详情页被分享到 **WhatsApp / Telegram / Facebook / 微信** 时，显示漂亮的分享卡片（标题 + 描述 + 图片）。

### 8.1 通用 OG 标签（WhatsApp/Telegram/Facebook 用）

在订单页与商品详情页 `<head>` 输出：

```html
<meta property="og:title" content="...">
<meta property="og:description" content="...">
<meta property="og:image" content="...">
<meta property="og:url" content="...">
<meta property="og:type" content="website">
<meta name="twitter:card" content="summary_large_image">
```

- **商品详情页**：主站 products 表已有 ogTitle / ogDescription / ogImage 字段，直接输出（已具备，核对生效即可）。
- **订单页**：og:title =「客户名 · 订单（懿泉茶业）」，og:description = 订单摘要（如"金骏眉 ×1、茉莉飘雪 ×2 · 已发货"），og:image = 订单首件商品主图（无则品牌 Logo）。

### 8.2 微信特殊处理（重点）

微信内分享**不完全依赖 og:* 标签**，主要抓取：
1. `<title>` 标签（最重要，微信卡片标题取 title）；
2. 页面正文第一张 `<img>`（微信卡片缩略图，通常取第一张图）；
3. `<meta name="description">`（描述）。

因此订单页/详情页需保证：`<title>` 精确、页面首图是商品图、`description` 存在。

**可选增强（开发评估工作量，非本期必做）**：接入微信 JS-SDK（`wx.config` + `updateAppMessageShareData` 自定义分享），需要已认证公众号 + 配置 JS 接口安全域名。因订单客户多为海外用户，本期**先做基础标签 + 微信友好 meta**，JS-SDK 作为后续可选。

## 12. 需 Qoder 特别留意的技术点

1. `/o/[orderNo]` 在 [locale] 外，注意 middleware 放行与 noindex；
2. 订单页语言：无 locale 前缀，需按订单 lang 指定 next-intl locale 渲染；
3. 商品删除与订单引用的关系（建议"已引用则显示占位"，保留历史）；
4. `showOnStorefront` 与 `status` 的语义区分（前台隐藏 ≠ 停用）；
5. 订单选商品要能选到 `showOnStorefront=false` 的商品；
6. 微信 OG 依赖 `<title>` + 首图 + description，非 og:* 优先；
7. 订单号唯一约束 + 自动生成规则（YQ-日期-客户缩写-序号）；
8. 详情页模块自适应显隐：origin/process/brewingGuide/description 各字段独立判空，空则不渲染对应模块（不要输出空标题/空白占位）；与主站拖拽布局的优先级（自动显隐兜底，拖拽为可选增强，注意二者不要互相覆盖导致模块消失）。
