# 懿泉茶业 YiQuanTea.com — 开发执行指南

> **版本**: v1.0（Cloudflare 全栈版） | **日期**: 2026-08-11
>
> **本文档定位**：给 AI 开发者（小龙虾）的"施工分阶段指令"——从零开始构建整个项目的完整执行计划。
> **使用方式**：逐阶段执行，每阶段完成后验证通过再进入下一阶段。不跳步、不赶工期。

---

## 施工原则

1. **质量第一，不赶工期**——每个阶段独立可验证
2. **移动端优先**——先做手机版再做桌面版
3. **每阶段写完必须验证**——构建零错误才算通过
4. **所有技术名词**——第一次出现必须加注释解释
5. **所有按钮**——必须有图标+汉字
6. **所有输入框**——必须有标签+占位提示+说明文字

---

## 阶段 1：项目初始化

**输入**：空文件夹

**产出**：可启动的空项目骨架

```
1. 在 D:\Users\Administrator\Desktop\yiquante.com-cloudflare 创建 Next.js 14 项目
2. 安装所有依赖（drizzle-orm, @neondatabase/serverless, jose, @cloudflare/next-on-pages 等）
3. 复制 .env.example → .env（留空待填）
4. 创建 compete 目录结构（src/app, drizzle/schema, messages, seed 等）

```

**验证**：`npm run dev` 能启动，`npm run build` 零错误

## 阶段 2：数据库 Schema

```
1. 创建 drizzle/schema/ 下所有 33 张表的 Drizzle 定义文件
2. 定义表间关系（references、unique、index）
3. 运行 drizzle-kit generate 生成迁移

```

**验证**：`npx drizzle-kit studio` 能看到 33 张表

## 阶段 3：核心工具库

```
编写 src/lib/ 下 11 个工具文件：
- db.ts（Neon + Drizzle 客户端）
- auth.ts（JWT 签发/校验/密码哈希/权限检查）
- kv.ts（KV 读写封装，本地开发用 Map fallback）
- r2.ts（R2 上传/下载/删除）
- db-d1.ts（D1 配置读写）
- i18n.ts（IP→语言映射）
- rate-limit.ts（KV 计数限流）
- email.ts（Gmail SMTP 邮件发送，开发阶段打日志）
- images.ts（Cloudflare Images URL 构造，开发阶段返回 R2 URL）
- backup.ts（数据库冷备导出存 R2）
- gdpr.ts（欧盟判定 + 同意记录）
- utils.ts（通用工具函数）
```

**验证**：每个工具文件单独可 import 无报错

## 阶段 8：API 路由（分 3 批）

**批次 A（认证+分类+B2B）：** auth / categories / showcase（分类/密码/Token/产品）

**批次 B（产品）：** products / products/[id] / products/[id]/layout / products/[id]/videos

**批次 C（业务）：** inquiries / samples / upload / config / logs / staff / stats / analytics / backup / gdpr / qrcode / search / ip-detect / search-keywords

每个 API 端点需包含：
- 认证校验 / 公开放行
- 输入验证（zod schema）
- 限流检查（公开接口 60次/分钟）
- 错误处理

**验证**：每个端点用 curl 测试返回正确响应
