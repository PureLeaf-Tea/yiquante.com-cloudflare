## 第一步：安装必要的软件

### 1.1 安装 Node.js（项目运行环境）

> Node.js 就是你电脑上跑这个网站项目需要用到的"引擎"，没有它代码跑不起来。

1. 打开浏览器，访问：https://nodejs.org
2. 点击左边的绿色大按钮（LTS 版本，最稳定）
3. 下载完成后，双击打开安装文件
4. 一路点"Next"（下一步），全部保持默认选项，直到安装完成
5. 验证安装成功：
   - 按键盘上的 `Win + R`（Windows 图标键 + R 键）
   - 输入 `cmd`，按回车
   - 在弹出的黑色窗口里输入：`node -v`
   - 回车后如果显示一串数字（比如 `v20.x.x`），说明安装成功 ✅
   - 再输入：`npm -v`，回车
   - 如果显示一串数字（比如 `10.x.x`），说明 npm 也装好了 ✅

### 1.2 安装 Git（代码版本管理工具）

> Git 用来下载代码、提交修改。装了就行，平时基本不用管它。

1. 打开浏览器，访问：https://git-scm.com/download/win
2. 下载会自动开始，如果没有自动开始，点页面上的"Click here to download manually"
3. 下载完成后，双击打开安装文件
4. **重要**：一路点"Next"，但到了「Choosing the default editor」这一步时，把下拉框的选项改成 **"Use Notepad as Git's default editor"**（用记事本作为默认编辑器）
5. 其余全部保持默认选项，直到安装完成
6. 验证安装成功：
   - 打开命令窗口（Win + R → 输入 `cmd` → 回车）
   - 输入：`git --version`
   - 回车后显示版本号就成功了 ✅

## 第二步：下载项目代码

### 2.1 获取代码（两种方式，选一种）

**方式一：公司有 GitHub 仓库（推荐）**

1. 打开命令窗口（Win + R → `cmd` → 回车）
2. 输入以下命令（把 `<仓库地址>` 替换为公司实际的 GitHub 地址）：
   ```
   cd D:\Users\Administrator\Desktop
   git clone <仓库地址> yiquante.com-cloudflare
   ```
3. 等它跑完，桌面上会出现 `yiquante.com-cloudflare` 文件夹 ✅

**方式二：直接复制文件夹**

1. 把公司给的 `yiquante.com-cloudflare` 文件夹整个复制到 `D:\Users\Administrator\Desktop\` 下面即可 ✅

### 2.2 安装项目依赖

> 项目依赖就是项目运行需要的"零件"，第一次拿到代码必须装。

1. 打开命令窗口
2. 输入以下命令（复制粘贴后按回车）：
   ```
   cd D:\Users\Administrator\Desktop\yiquante.com-cloudflare
   npm install
   ```
3. 等待安装完成（可能需要 2-5 分钟，网络不好的话会更久）
4. 安装成功后会显示类似 `added XXX packages in XXs` 的字样 ✅

## 第三步：注册云服务账号并获取密钥

> ⚠️ 这一步需要公司管理员来做，因为涉及账号绑定和实名认证。
> 开发阶段可以先跳过这一步，代码里预留了占位，不影响开发。

### 3.1 注册 Cloudflare 账号

1. 打开浏览器，访问：https://dash.cloudflare.com/sign-up
2. 输入公司邮箱（或管理员邮箱），设置密码
3. 注册完成后登录进入 Cloudflare 控制台（后台管理页面）

### 3.2 添加域名到 Cloudflare

> ⚠️ 前提：域名 `yiquantea.com` 已经购买好了。

1. 在 Cloudflare 控制台首页，点击「+ 添加站点」
2. 输入 `yiquantea.com`，点击「继续」
3. 选择 Free 套餐（免费），点击「继续」
4. Cloudflare 会扫描现有的 DNS 记录，扫描完点「继续」
5. 关键步骤：Cloudflare 会给你两个新的 DNS 服务器地址（叫 nameserver）
   - 比如：`alice.ns.cloudflare.com` 和 `bob.ns.cloudflare.com`
6. 记下这两个地址，去你买域名的地方（比如阿里云、GoDaddy）
7. 在域名管理里找到「DNS 修改」或「修改 DNS 服务器」
8. 把原来的 DNS 服务器替换成 Cloudflare 给的两个地址
9. 保存，等待生效（一般几分钟到几小时）
10. Cloudflare 检测到 DNS 切换完成后，站点状态变成「Active」✅

### 3.3 注册并配置 Neon 数据库

1. 打开浏览器，访问：https://neon.tech
2. 点击「Sign Up」，用 GitHub 或 Google 账号注册（推荐 GitHub）
3. 登录后，点击「Create project」
4. 输入项目名称：`yiquantea`
5. 数据库名称保持默认：`neondb`
6. Region（地区）选择离目标客户最近的（比如欧洲客户多就选 Frankfurt）
7. 点击「Create project」
8. 创建成功后，页面会显示一个连接字符串（Connection string），长这样：
   ```
   postgresql://neondb_owner:xxxxx@ep-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
9. **复制这串地址，保存到安全的地方**（这就是下一步要填的 `DATABASE_URL`）✅

### 3.4 创建 R2 存储桶

1. 在 Cloudflare 控制台左侧菜单，找到「R2」
2. 点击「创建存储桶」
3. 存储桶名称输入：`yiquantea-assets`
4. 位置选择「自动」（Automatic）
5. 点击「创建存储桶」✅
6. 接着创建 API Token（访问密钥）：
   - R2 页面 → 右上角「管理 API 令牌」
   - 点击「创建 API 令牌」
   - 权限选「对象读取和写入」（Object Read & Write）
   - 创建后在弹窗中复制「Access Key ID」和「Secret Access Key」
   - **这两个值只显示一次，赶紧保存！** ✅

### 3.5 创建 KV 命名空间

1. Cloudflare 控制台左侧 → 「Workers & Pages」→ 顶部菜单「KV」
2. 点击「创建命名空间」
3. 名称：`YIQUANTEA-KV`
4. 点击「创建」✅
5. 返回列表，记下这个命名空间的 ID（一串字母数字）

### 3.6 创建 D1 数据库

1. Cloudflare 控制台左侧 → 「Workers & Pages」→ 顶部菜单「D1」
2. 点击「创建数据库」
3. 名称：`yiquantea-d1`
4. 位置：保持默认
5. 点击「创建」✅
6. 记下数据库 ID

### 3.7 注册 Resend 邮件服务

> Resend 是用来发邮件的服务（纯 HTTP 接口，Cloudflare Workers 原生支持）。

1. 打开浏览器，访问：https://resend.com
2. 点击「Sign Up」注册账号（用公司邮箱 `yqtea.cn@gmail.com`）
3. 登录后，点击左侧「Domains」→「Add Domain」
4. 输入域名：`yiquantea.com`
5. 按页面提示在 Cloudflare DNS 里添加验证记录（几条 TXT 和 MX 记录）
6. 验证通过后（可能等几分钟），点击左侧「API Keys」
7. 点击「Create API Key」→ 复制生成的密钥（长这样：`re_xxxxx`）
8. **复制并保存**（这就是 `RESEND_API_KEY`）✅

## 第四步：配置项目环境变量

> 环境变量就是项目的"配置单"，告诉代码数据库在哪、密钥是什么。填在 `.env` 文件里。

### 4.1 创建 .env 文件

1. 在项目根目录（`D:\Users\Administrator\Desktop\yiquante.com-cloudflare\`）下
2. 新建一个文本文件，命名为 `.env`（注意：前面有个点，没有 `.txt` 后缀名）
3. 如果 Windows 不让你创建 `.env` 开头的文件名，用命令行创建：
   ```
   cd D:\Users\Administrator\Desktop\yiquante.com-cloudflare
   copy .env.example .env
   ```
4. 如果连 `.env.example` 也没有，手动新建后用记事本打开，把下面内容填进去

### 4.2 环境变量清单（逐项填写）

用记事本打开 `.env` 文件，按下面的格式填写，一行一个配置项：

```bash
# ============ 数据库（Neon）============
DATABASE_URL="postgresql://neondb_owner:xxxxx@ep-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require"
# ↑ 把第三步 §3.3 保存的连接地址复制过来

# ============ Cloudflare R2（文件存储）============
R2_ACCOUNT_ID="你的Cloudflare账户ID（在Cloudflare后台右上角）"
R2_ACCESS_KEY_ID="第三步§3.4保存的Access Key ID"
R2_SECRET_ACCESS_KEY="第三步§3.4保存的Secret Access Key"
R2_BUCKET_NAME="yiquantea-assets"
R2_PUBLIC_URL="https://pub-xxx.r2.dev（R2存储桶的公开访问URL）"

# ============ Cloudflare KV（高速缓存）============
KV_NAMESPACE_ID="第三步§3.5保存的KV命名空间ID"

# ============ Cloudflare D1（轻量数据库）============
D1_DATABASE_ID="第三步§3.6保存的D1数据库ID"

# ============ JWT认证密钥 ============
AUTH_SECRET="随机生成：在命令行输入 node -e "console.log(require('crypto').randomBytes(32).toString('base64'))" 复制输出"
# ↑ 一行命令生成，输出结果贴过来

# ============ 超级管理员 ============
ADMIN_USERNAME="13333827003"
ADMIN_PASSWORD="由公司决定（首次登录后强制修改）"

# ============ B2B展示区密码加密密钥 ============
SHOWCASE_PASSWORD_KEY="随机生成32位字符串（同样用上面的命令生成）"

# ============ 邮件发送（Resend）============
RESEND_API_KEY="re_***"
# ↑ 从 Resend 后台（resend.com）→ API Keys 获取

# ============ 网站地址 ============
NEXT_PUBLIC_SITE_URL="https://yiquantea.com"
# 本地开发时写 http://localhost:3000，上线后改回正式地址

# ============ hCaptcha 人机验证（可选，开发阶段可不填）============
NEXT_PUBLIC_HCAPTCHA_SITE_KEY="（留空，上线前再填）"
HCAPTCHA_SECRET_KEY="（留空，上线前再填）"

# ============ 备份设置 ============
BACKUP_RETENTION_DAYS=7

# ============ 限流设置 ============
RATE_LIMIT_PUBLIC=60
RATE_LIMIT_LOGIN=5
```

### 4.3 填完后检查

- [ ] `DATABASE_URL` 已正确填写
- [ ] R2 相关 4 个变量已填写
- [ ] `AUTH_SECRET` 和 `SHOWCASE_PASSWORD_KEY` 是随机生成的
- [ ] `ADMIN_USERNAME` 是正确的手机号
- [ ] 没有多写空格、没有多写引号

> 现在所有准备工作完成，可以启动项目了。

## 第六步：初始化数据库和种子数据

> 种子数据（Seed Data）就是第一次使用时自动填充的演示数据——初始分类、示例产品、B2B分类密码等。

### 6.1 生成数据库表结构

```
npm run db:push
```

这一步会根据代码里的表定义，在 Neon 数据库里自动创建好所有 33 张表。输出类似 `Table created: products` 等。

### 6.2 填充种子数据

```
npm run db:seed
```

这一步会：
- 创建管理员账号（手机号 + 密码）
- 创建 8 个一级分类和子分类
- 创建 2 个 B2B 展示区分类（自带密码）
- 创建 14 款示例茶叶产品
- 创建导航菜单、网站设置、客户评价等

### 6.3 验证数据库有没有弄好

```
npm run db:studio
```

这会打开一个网页（http://localhost:5555），可以在上面看到数据库里所有表的数据。确认 `products` 表里有 14 条数据、`categories` 表里有分类树，就说明种子数据跑成功了 ✅

## 上线发布步骤

### 什么时候需要做这一步？

- 项目第一次上线时
- 修复了 bug 需要更新时
- 新增了功能需要更新时

### 8.1 连接 GitHub 到 Cloudflare Pages（第一次上线）

> 前提：代码已经推送到公司 GitHub 仓库。

1. 登录 Cloudflare 控制台（https://dash.cloudflare.com）
2. 左侧菜单 → 「Workers & Pages」→ 顶部标签「Pages」
3. 点击「连接到 Git」
4. 选择 GitHub → 授权 Cloudflare 访问代码仓库
5. 选择 `yiquantea-com` 仓库
6. 配置构建设置：
   - **框架预设**：Next.js
   - **构建命令**：`npm run build`
   - **构建输出目录**：`.vercel/output/static`
   - **根目录**：`/`（保持默认）
7. 点击「保存并部署」
8. 等待部署完成（一般 2-5 分钟）
9. 部署成功后，Cloudflare 会提供一个预览地址（比如 `yiquantea-com.pages.dev`）
10. 验证预览地址能正常打开 ✅
11. 在「自定义域」选项卡里添加 `yiquantea.com`（前提是域名已在 Cloudflare 里管理）
12. 几分钟后，访问 `https://yiquantea.com` 就能看到线上网站了 ✅

### 8.2 配置 Workers 路由

网站跑起来后，API 接口（Workers）也需要上线：

1. Cloudflare 控制台 → 「Workers & Pages」→ 「创建应用程序」→ 「创建 Worker」
2. 命名为 `yiquantea-api`
3. 在 Worker 的「设置」→ 「触发器」里配置路由：
   - 路由：`yiquantea.com/api/*`
4. 在 Worker 的「设置」→ 「变量」里，把 `.env` 文件中的环境变量全部添加进去
5. 绑定 KV（`YIQUANTEA-KV`）、D1（`yiquantea-d1`）、R2（`yiquantea-assets`）
6. 点击「部署」

### 8.3 配置 Cron 定时任务

1. 在 Worker 的 `wrangler.toml` 配置文件中添加：
   ```toml
   [triggers]
   crons = ["0 3 * * *", "0 4 * * *"]
   ```
2. 部署后，Cloudflare 会自动在每天凌晨 3 点和 4 点（UTC 时间）执行备份和清理任务

## 回滚步骤（出问题了怎么退回去）

> 如果上线后发现有问题，别慌，下面的方法可以把网站恢复到上一个正常版本。

### 9.1 一键回滚（最简单，推荐优先用）

1. 登录 Cloudflare 控制台 → 「Workers & Pages」→ 找到项目
2. 点击「部署」标签
3. 找到上一个正常工作的部署版本
4. 点击版本右侧的「⋯」菜单 → 选择「回滚到此版本」
5. 确认回滚
6. 等 1-2 分钟，网站就恢复到上一个版本了 ✅

### 9.2 数据库回退（如果数据被误删了）

> ⚠️ Neon 自带时间点恢复，不需要额外操作。

1. 登录 Neon 控制台（https://console.neon.tech）
2. 找到项目 → 点击「Branches」
3. 点击「Restore」→ 选择出问题之前的时间点
4. 恢复完成后，数据库回到那个时间点的状态

### 9.3 最坏情况下：临时切回老网站

> 如果新网站完全不能用，可以切回老网站的域名指向

1. 登录 Cloudflare 控制台 → 选择 `yiquantea.com`
2. 点击「DNS」→ 找到主域名记录（A 记录或 CNAME 记录）
3. 把记录改为老服务器的 IP 地址
4. 保存，几分钟后生效 ✅

## 日常更新步骤

每次你改了代码想更新线上网站，就做这几步：

### 10.1 提交代码

1. 打开命令窗口，进入项目目录
2. 查看改了什么：
   ```
   git status
   ```
3. 把所有改动加入提交：
   ```
   git add .
   git commit -m "描述你改了什么（比如：修复了产品图片不显示的问题）"
   ```
4. 推送到 GitHub：
   ```
   git push
   ```

### 10.2 自动部署

推送到 GitHub 后，Cloudflare Pages 会自动检测到更新，自动重新构建并部署。不需要做任何额外操作。等 2-5 分钟后刷新网站就能看到更新了。

## 常见卡住问题

| 现象 | 可能原因 | 解决方法 |
|:-----|:-----|:-----|
| 命令窗口里打 `node -v` 没反应 | Node.js 没装好 | 重新安装 Node.js，安装时注意勾选"Add to PATH" |
| `npm install` 报错 | 网络不好，下载不下来 | 多试几次，或者换成手机热点试试 |
| `npm run dev` 后浏览器打不开 localhost:3000 | 端口被占用 | 试一下 http://localhost:3001，或者重启电脑 |
| 能看到首页但点产品没数据 | 数据库没连接上 | 检查 `.env` 里的 `DATABASE_URL` 有没有填对 |
| 图片显示不出来 | R2 没配置或图片没上传 | 开发阶段先不管，上线前确认 R2 配置 |
| `npm run db:push` 报错 | 数据库连接字符串有问题 | 去 Neon 后台检查连接字符串是否最新（密码过期的可能性大） |
| 登录后台失败 | 管理员账号没创建或密码错了 | 跑 `npm run db:seed` 重新创建管理员，或用 `npm run db:studio` 查看 users 表 |
| Cloudflare Pages 部署后打不开 | DNS 没生效或构建失败 | 去 Pages 后台看"部署"标签的日志，里面有具体错误信息 |
