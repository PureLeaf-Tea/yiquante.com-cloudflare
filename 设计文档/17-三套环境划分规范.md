# 懿泉茶业 YiQuanTea.com — 三套环境划分规范

> **版本**: v1.0 | **日期**: 2026-08-11
>
> **本文档定位**：明确本地开发、预览、生产三套环境的隔离规则，避免测试数据污染生产环境。
> **阅读对象**：开发人员 + 管理员。

---

## 一、三套环境定义

| 环境 | 用途 | 谁在用 | 网址 |
|:-----|:-----|:-----|:-----|
| **本地开发**（Local） | 开发人员写代码和调试 | 开发人员 | `http://localhost:3000` |
| **预览环境**（Preview） | 开发完成后的测试验证 | 开发 + 内部测试人员 | Cloudflare Pages 自动生成的预览 URL（如 `xxx.pages.dev`） |
| **生产环境**（Production） | 正式对外服务的网站 | 全体员工 + 客户 | `https://yiquantea.com` |

|:-----|:-----|
| 代码来源 | GitHub 的 `main` 或 `preview` 分支 |
| 触发方式 | 推送到 `main` 分支时自动部署 |

- 测试完成后，手动把 preview 数据库删掉重建

## 三、隔离规则（必须遵守）

### ❌ 绝对禁止的操作

1. **本地开发直连生产数据库**——可能导致误删生产数据
2. **预览环境用生产 API Key**——预览环境的邮件/hCaptcha 用测试密钥
3. **生产环境用测试数据**——种子数据只跑在开发和预览环境
4. **手动在生产数据库里改数据**——所有操作必须通过后台页面

### ✅ 正确操作方式

| 场景 | 正确做法 |
|:-----|:-----|
| 开发新功能 | 本地开发 → 本地测试 → 推送到 main → 自动部署到预览环境 → 在预览环境验证 |
| 修复 bug | 同"开发新功能"流程 |
| 发布到生产 | 预览环境验证通过 → 手动触发生产部署 → 上线后监控 |
| 查看生产数据 | 通过后台页面查看，不要直接连数据库 |
| 恢复生产数据 | 用 Neon 控制台的时间点恢复功能 |
| 数据迁移 | 先在 preview 分支演练一遍，确认无误后再在 main 分支执行 |

## 四、环境变量管理

### 4.1 本地开发

`.env` 文件（不提交到 Git）：
```bash
DATABASE_URL="postgresql://.../neondb-dev"  # dev 分支
RESEND_API_KEY="re_test_xxx"                # Resend 测试密钥
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
NEXT_PUBLIC_HCAPTCHA_SITE_KEY="10000000-ffff-ffff-ffff-000000000000"  # hCaptcha 测试密钥
```

### 4.2 预览环境

通过 Cloudflare Pages 后台 → 环境变量 设置：
```bash
DATABASE_URL="postgresql://.../neondb-preview"
RESEND_API_KEY="re_test_xxx"               # 和本地一样用测试密钥
NEXT_PUBLIC_SITE_URL="https://xxx.pages.dev"
```

### 4.3 生产环境

通过 Cloudflare Pages 后台 → 环境变量 设置：
```bash
DATABASE_URL="postgresql://.../neondb"     # main 分支
RESEND_API_KEY="re_live_xxx"              # Resend 正式密钥
NEXT_PUBLIC_SITE_URL="https://yiquantea.com"
NEXT_PUBLIC_HCAPTCHA_SITE_KEY="正式密钥"
```

## 五、发布流程

```
本地开发完成
    │
    ├── npm run build（本地构建验证零错误）
    ├── 本地功能测试通过
    │
    ▼
git commit + git push（推送到 GitHub main 分支）
    │
    ├── Cloudflare Pages 自动部署到预览环境
    ├── 在预览环境测试（检查清单见 16 号文档）
    │
    ├── 预览环境验证全部通过 ✅
    │
    ▼
手动触发生产部署
    │
    ├── 在 Cloudflare Pages → 部署 → 选择预览环境通过的版本 → "Promote to Production"
    │
    ▼
生产环境上线
    │
    ├── 监控 1-2 小时
    ├── 如有问题 → Cloudflare Pages 一键回滚到上一个版本
    │
    ▼
完成 ✅
```

## 六、回滚流程

> 生产环境出问题时，快速回退到上一个正常版本。

### 6.1 前端回滚（最快，1-2 分钟生效）

1. 登录 Cloudflare Pages 后台
2. 找到项目 → 「部署」标签
3. 找到上一个正常的部署版本
4. 点击「⋯」→ 「回滚到此版本」
5. 确认

### 6.2 数据库回滚（如需要）

1. 登录 Neon 控制台
2. 项目 → 「Branches」→ main 分支 → 「Restore」
3. 选择出问题之前的时间点
4. 恢复完成（仅影响数据库，不影响前端代码）
