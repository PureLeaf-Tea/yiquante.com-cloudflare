## 一、大白话架构说明

### 1.1 简单一句话

**老版**：在一个服务器（电脑）上，自己装数据库、自己存图片、自己管理一切，就像一个单体大仓库，所有东西堆在一起。

**新版**：把网站拆成几块，每一块用 Cloudflare 生态里最专业的服务来管——网页放在 Pages（全球加速的网页托管）、产品数据放在 Neon（云端数据库）、图片视频放在 R2（专门存文件的仓库）、高频读写放在 KV（超快小缓存）。每一块都是独立运转的，某个服务出问题不会拖垮整个网站。

### 1.2 每个服务的角色（大白话说）

| 服务 | 通俗理解 | 管什么 |
|:-----|:---------|:------|
| **Cloudflare Pages**（网页托管） | 把你的网站页面放到全球每一个角落的服务器上，客户从哪个国家访问都很快 | 网站所有页面、前端代码 |
| **Cloudflare Workers**（后端接口） | 在 Cloudflare 全球网络上运行的小程序，处理客户登录、查产品、提交询价等操作 | 所有 API 接口、业务逻辑 |
| **Neon Serverless PostgreSQL**（数据库） | 放在云上的数据库，不用自己装、不用自己修，自动备份，随时恢复 | 产品信息、分类、询价记录、用户账号等 33 张业务表 |
| **Cloudflare KV**（高速缓存） | 全球同步的微型快取，读写极快，适合存临时数据 | 访问频率限制计数、B2B 24 小时访问 token、首页配置缓存 |
| **Cloudflare D1**（轻量数据库） | Cloudflare 自己做的轻量级小数据库，适合存配置类小数据 | 仅存浏览分析快照数据 |
| **Cloudflare R2**（文件仓库） | 专业存文件的仓库，存图片、视频，不按流量收费（这点很关键） | 产品图片、360°展示图、产品视频、备份文件 |
| **Cloudflare Images**（图片处理） | 自动压缩、剪裁、转换格式，不用每次手动修图 | 把原图自动变成适合网页的大小和格式 |
| **Cloudflare DNS**（域名管理） | 域名解析服务——网址访问、SSL 证书、DDoS 防护全在这里管 | yiquantea.com 域名的所有设置 |

> 📝 施工中变更：①登录状态实际用无状态 JWT（httpOnly Cookie，jose 签发校验），KV 不存 session；②网站设置（site_config）与 GDPR 同意记录（gdpr_consents）实际存 Neon，D1 按最终分工仅存分析快照（与 wrangler.toml 注释一致）

> **一句话总结**：Pages 管页面、Workers 管逻辑、Neon 管数据、R2 管文件、KV/D1 管缓存和配置——各干各的，互不拖累。

### 1.3 为什么比老版好？（说人话）

| 对比维度 | 老版 v3.0 | 新版 Cloudflare 版 | 好在哪 |
|:-----|:-----|:-----|:-----|
| **全球访问速度** | 服务器在哪儿，速度就在哪儿；海外客户隔着半个地球访问很慢 | 全球 300+ 节点，客户附近的节点直接响应，延迟降低 5-10 倍 | 海外客户打开网站跟打开本地网站一样快 |
| **服务器维护** | 自己买 VPS（虚拟服务器）、装系统、打补丁、半夜出问题还得爬起来修 | 完全不用管服务器，Cloudflare 全托管 | 不用雇人维护服务器，也不用自己学运维 |
| **扛流量能力** | 流量大了得升级服务器、加配置，属于"搬砖"式扩容 | 自动弹性扩容，来多少人都不怕，Cloudflare 自己扛 | 不会因为上了热搜突然挂掉 |
| **数据安全** | 服务器被攻击、硬盘坏了、误删数据都可能导致数据丢失 | 所有服务自带备份和容灾，出问题能回退到任意时间点 | 数据安全性提升好几个档次 |
| **成本** | 每月固定服务器费用 + 带宽费 + 维护人力 | 初期流量小，全部在免费额度内；量大了按需付费 | 初期零成本，中期按需升 |

## 二、新老版本一一对应表

> 左边是老版 v3.0 的组件，右边是新版的替代方案，中间解释换了之后有啥不一样。

### 2.1 核心基础设施

| 老版 v3.0 | 新版 Cloudflare 版 | 换了之后有啥不一样 |
|:-----|:-----|:-----|
| Docker 容器部署 | Cloudflare Pages（网页托管） | 不用自己写 Docker 配置文件了，代码推到 GitHub 自动部署，回滚点一下就行 |
| Nginx 反向代理 | Cloudflare DNS 自带代理 | SSL 证书自动签发续期、DDoS 攻击自动防护，不用自己配置 Nginx |
| Node.js 服务器（持续运行） | Cloudflare Workers（按需运行） | 老版服务器 24 小时开着，新版只有访问时才启动，不访问不花钱 |
| PostgreSQL + Docker | **Neon Serverless PostgreSQL** | 不用装数据库、不用配备份策略，自带时间点恢复，支持一键建分支做测试 |
| Redis 缓存 | **Cloudflare KV**（高速缓存） | 全球同步延迟更低，不用装 Redis，直接用，数据自动同步到所有节点 |
| 本地磁盘 + OSS 存图 | **Cloudflare R2**（文件仓库） | 不用买对象存储，不限流量出站费（这点阿里云 OSS 做不到），国际访问更快 |
| node-cron 定时备份 | **Neon PITR + Workers Cron + R2 冷备** | 原来的定时 pg_dump 方式废弃，改为 Neon 自带的 6 小时时间窗口恢复 + Workers 定时任务导出备份存 R2 |
| sharp 图片压缩 | **Cloudflare Images** | 不用在代码里处理图片了，上传原图到 R2，Cloudflare Images 自动压缩转格式 |

### 2.2 技术框架

| 老版 v3.0 | 新版 Cloudflare 版 | 换了之后有啥不一样 |
|:-----|:-----|:-----|
| Prisma ORM（数据库操作框架） | **Drizzle ORM**（数据库操作框架） | Prisma 在 Cloudflare Workers 上跑不了（要额外花钱买加速服务），Drizzle 天生支持，免费，代码更轻 |
| NextAuth.js 认证 | **jose（JWT 生成校验库）** | 自己写一套简单的登录逻辑，不再依赖第三方认证库，代码透明好调试，适配 B2B 权限更灵活 |
| bcryptjs 密码加密 | **Web Crypto API (SHA-256)** | Cloudflare Workers 里直接用浏览器级别的加密 API，不依赖外部库，速度更快 |
| geoip-lite IP 定位 | **Cloudflare Workers `request.cf.country`** | Cloudflare 自带的 IP 地理信息，不依赖任何外部库，直接取，永远准确 |
| node-cron 定时任务 | **Workers Cron Triggers**（定时触发器） | Cloudflare 原生的定时任务功能，在 Workers 里设个时间表达式就行，稳定可靠 |
| @dnd-kit 拖拽 | **@dnd-kit**（保持不变） | 前端代码在 Pages 上照常运行，纯浏览器端的库不用换 |
| video.js 视频播放 | **video.js**（保持不变） | 同上，前端组件不受影响 |

### 2.3 功能对比（体验层面）

| 功能 | 老版 v3.0 | 新版 Cloudflare 版 | 客户/员工感受变化 |
|:-----|:-----|:-----|:-----|
| 前台浏览产品 | 正常 | 正常 | **完全没变**，操作一模一样 |
| 6 语言切换 | 正常 | 正常 | **完全没变**，使用方式相同 |
| B2B 加密区 | 独立密码 + 24h token | 独立密码 + 24h token | **完全没变**，密码输入体验一致 |
| 在线询价 | hCaptcha 验证 | hCaptcha/Turnstile 验证 | **完全没变**，客户填完提交就行 |
| 在线聊天 | 15 秒轮询 | 5 秒轮询（后期升 WebSocket 实时推送） | **目前一样**，后期消息推送更即时 |
| 样品申请 | 提交表单 | 提交表单 | **完全没变** |
| 后台管理 | 浏览器登录操作 | 浏览器登录操作 | **完全没变**，按钮、菜单、操作逻辑一模一样 |
| 产品图片 | 本地存储 | R2 存储 | **完全没变**，员工还是上传图片，系统自动处理 |
| 自动备份 | pg_dump 定时备份 | Neon 自带 PITR + R2 冷备 | 恢复更快、更灵活，后台能看到备份状态 |
| 网站速度 | 取决于服务器位置 | 全球加速 | **客户感觉打开更快了**，尤其是海外客户 |

> 📝 施工中变更：聊天轮询间隔实际实现为 5 秒（ChatWidget setInterval 5000ms），非原定的 15 秒

## 三、成本明细对照表

### 3.1 各服务费用明细

| 服务 | 免费额度 | 我们当前 1G 数据用多少 | 什么时候开始花钱 | 预估每月最高费用 |
|:-----|:-----|:-----|:-----|:-----|
| **Cloudflare Pages**（网页托管） | 无限请求、无限带宽 | 完全在免费额度内 | 基本不会超 | **¥0** |
| **Cloudflare Workers**（后端接口） | 每天 10 万次请求 | 初期每天几千次 | 日请求超 10 万次（需要日均活跃用户几千人） | **¥0 → 超了约 $5/月**（1000 万次请求） |
| **Neon Serverless PostgreSQL**（数据库） | 0.5 GB 存储 + 100 小时计算时间/月 | 33 张表全装进去在 100-200MB 左右 | 数据量超过 0.5GB 或计算时间超 100 小时 | **¥0 → 超了约 $19/月（Pro 套餐）** |
| **Cloudflare KV**（高速缓存） | 每天 10 万次读、1000 次写 | 完全在免费额度内 | 日读写超额度 | **¥0** |
| **Cloudflare D1**（轻量数据库） | 5 GB 存储、每天 500 万次读 | 预聚合分析数据，完全在免费额度内 | 基本不会超 | **¥0** |
| **Cloudflare R2**（文件仓库） | 10 GB 存储、A 类操作 100 万次/月、B 类 1000 万次/月 | 1GB 存储，几百次上传/月 | 存储超 10GB 或操作超免费额度 | **¥0** |
| **Cloudflare Images**（图片处理） | 每月 5000 次唯一图片变换 | 几百张产品图 × 几种尺寸，在免费额度内 | 唯一图片数超 5000 | **¥0**（超了按 $1/1000张 付费） |
| **Cloudflare DNS**（域名管理） | 完全免费 | 完全免费 | 永远免费 | **¥0** |
| **Resend**（邮件发送） | 每天 100 封 | 初期每天十几封 | 日发超 100 封 | **¥0 → 超了约 $20/月** |
| **hCaptcha**（人机验证） | 每月 100 万次 | 完全在免费额度内 | 基本不会超 | **¥0** |

### 3.2 费用总结

| 阶段 | 月费用 | 触发条件 |
|:-----|:-----|:-----|
| **初期（0-6 个月）** | **¥0** | 流量小，所有服务免费额度绰绰有余 |
| **成长期（6-18 个月）** | **约 ¥100-200/月** | Neon Pro（$19/月，数据库扩容）+ Workers 付费套餐（$5/月） |
| **成熟期（18 个月以上）** | **约 ¥200-500/月** | 多个付费服务达到中等使用量 |

> 💡 **对比老版**：老版 VPS 服务器最少每月 ¥100-300（还不算维护人力），新版初期零成本，成长期持平，成熟期略高但换来的是全球加速、自动容灾、零运维。

### 3.3 什么情况下会突然花钱？

| 情况 | 会不会 | 说明 |
|:-----|:-----|:-----|
| 突然上了热搜/新闻，几万人涌进来 | **不会** | Workers 日请求超免费额度时会继续服务，Cloudflare 不会立刻断网，只是下个月账单可能多几块钱 |
| 员工大量上传高清图 | **基本不会** | R2 免费 10GB，我们总共才 1GB，还有 9 倍余量 |
| 被黑客攻击 | **不会** | Cloudflare 自带 DDoS 防护，免费套餐就有 |
| 忘了关什么服务 | **不会** | 所有付费服务都需要手动升级套餐，不会自动扣费 |

> ⚠️ **风险提示**：Neon 数据库的"计算时间"是唯一可能意外超额的指标。如果有人在短时间内大量刷新后台分析页面（每次都会查数据库），可能消耗计算时间。设计时会对分析数据做缓存，不会有这个问题，但需要留意。

## 四、上线前准备清单

> 按顺序完成，每个步骤都标注了谁负责、干什么、怎么拿密钥。

| 序号 | 步骤 | 用途 | 谁负责 | 怎么拿到对接信息 | 备注 |
|:--:|:-----|:-----|:-----|:-----|:-----|
| 1 | 注册 Cloudflare 账号 | 所有服务的基础平台 | 管理员 | 访问 [cloudflare.com](https://cloudflare.com) 注册 | 免费，用公司邮箱注册 |
| 2 | 在 Cloudflare 中添加 yiquantea.com 域名 | DNS 管理、SSL 证书、所有服务都绑定到这个域名 | 管理员 | 登录 Cloudflare → 添加站点 → 按指引修改域名 DNS 服务器 | 域名在哪买的就在哪改 DNS |
| 3 | 注册 Neon 数据库账号 | 核心数据库，存所有业务数据 | 管理员 | 访问 [neon.tech](https://neon.tech) 用 GitHub/Google 账号注册 | 免费套餐即可 |
| 4 | 在 Neon 中创建数据库项目 | 获取数据库连接地址 | 管理员 | Neon 后台 → Create project → 复制连接字符串 | 拿到 `.env` 中填的 DATABASE_URL |
| 5 | 创建 R2 存储桶 | 存图片、视频、备份文件 | 管理员 | Cloudflare 后台 → R2 → Create bucket → 命名 `yiquantea-assets` | 拿到 bucket 名称和 endpoint |
| 6 | 获取 R2 Access Key | 程序读写 R2 的凭证 | 管理员 | Cloudflare 后台 → R2 → Manage API Tokens → Create | 拿到 Access Key ID 和 Secret |
| 7 | 创建 KV 命名空间 | 存会话缓存、限流计数、B2B token | 管理员 | Cloudflare 后台 → Workers & Pages → KV → Create namespace → 命名 `YIQUANTEA-KV` | 拿到 KV namespace ID |
| 8 | 创建 D1 数据库 | 存站点配置、GDPR 记录、统计数据 | 管理员 | Cloudflare 后台 → Workers & Pages → D1 → Create database → 命名 `yiquantea-analytics` | 拿到 database ID |
| 9 | （可选）开通 Cloudflare Images | 图片自动压缩和格式转换 | 管理员 | Cloudflare 后台 → Images → 开通 | 开发阶段可不急着开，上线前再开 |
| 10 | 注册 hCaptcha 账号 | 询价/样品表单的人机验证 | 管理员 | 访问 [hcaptcha.com](https://hcaptcha.com) 注册 | 开发阶段可先占位，上线前激活 |
| 11 | 注册 Resend 邮件服务 | 发送确认邮件 | 管理员 | resend.com 注册 → 验证发件域名 → API Keys | 拿到 RESEND_API_KEY |
| 12 | 创建 GitHub 仓库 | 存代码 + 自动部署 | 管理员 | github.com 创建私有仓库 `yiquantea-com` | 把代码推上去，Cloudflare Pages 自动部署 |
| 13 | 连接 GitHub 到 Cloudflare Pages | 自动部署：代码更新了自动上线 | 管理员 | Cloudflare 后台 → Workers & Pages → Create → Pages → Connect Git | 选 GitHub 仓库 → 配置构建命令 |

> 📝 施工中变更：①步骤 8 的 D1 实际创建的库名为 `yiquantea-analytics`（见 wrangler.toml database_name），非原定的 `yiquantea-d1`；②步骤 11 邮件实际改用 Resend API（.env 中 RESEND_API_KEY），未使用原定的 Gmail App Password 方案

| `RATE_LIMIT_LOGIN` | 登录限流次数 | 固定值 `5`（每分钟） |

## 五、服务分工详解

### 5.1 数据怎么存的？

```
客户访问网站
    │
    ├── 看产品列表 → Workers 查 Neon 数据库 → 返回产品数据
    │                 ↓
    │              产品图片 URL 指向 R2
    │                 ↓
    │              图片经过 Cloudflare Images 压缩转格式
    │
    ├── 切换语言 → Workers 读 KV（缓存了用户语言偏好）→ 返回对应语言页面
    │
    ├── B2B 输密码 → Workers 验证密码（Neon 查加密密码）
    │                → 通过后发 token 存 KV（24小时有效）
    │                → 下次访问直接读 KV 验证 token
    │
    ├── 提交询价 → Workers 先查 KV 限流计数（有没有刷太多次）
    │             → 验证人机验证（hCaptcha）
    │             → 写入 Neon 数据库
    │             → 发邮件通知（Resend API）
    │
    └── GDPR 弹窗 → Workers 读 D1（之前有没有同意过）
                    → 没同意过 + 欧盟 IP → 显示弹窗
                    → 客户点同意 → 写 D1 记录
```

> 📝 施工中变更：①邮件实际通过 Resend API 发送（src/lib/email.ts），未使用 Gmail SMTP；②GDPR 同意记录实际存 Neon（gdpr_consents 表），非 D1

### 5.2 定时任务怎么跑的？

| 任务 | 时机 | 实现方式 |
|:-----|:-----|:-----|
| 数据库冷备 | 每天凌晨 3 点（上海时间） | Workers Cron Trigger → 执行备份脚本 → 导出 JSON 存到 R2 |
| 过期备份清理 | 每次备份后 | 备份脚本内置，删除 7 天前的 R2 文件 |
| 浏览日志清理 | 每天凌晨 4 点 | Workers Cron Trigger → 删除 90 天前的浏览日志 |

> 📝 施工中变更：①备份格式实际为 JSON（backup-*.json，含 31 张表导出），非 SQL；②Cron 定时任务尚未在 Workers 侧落地（src/worker.ts 未创建，wrangler.toml 的 crons 声明待部署时生效），当前备份由后台「备份管理」手动触发（POST /api/backup）

### 5.3 请求怎么走的？（一条完整链路）

以"一个匈牙利客户在布达佩斯打开 B2B 产品页"为例：

> 📝 施工中变更：本站六语言为 zh/en/ru/de/es/fr（不含匈牙利语 hu），示例 URL 由 /hu/ 改为 /en/

```
1. 客户在浏览器输入 yiquantea.com/en/b2b
2. DNS（Cloudflare DNS）解析 → 指向最近的 Cloudflare 节点（可能在法兰克福或布达佩斯附近）
3. Cloudflare Pages 返回已缓存的页面（静态部分）
4. 页面加载时，前端 JS 调 Workers API（/api/showcase/categories）
5. Workers 检查 KV：这个客户有没有 B2B token？
   ├── 有且有效 → 直接返回产品列表（Neon 查数据，KV 缓存结果）
   └── 无 → 返回"需要密码"，前端显示密码弹窗
6. 客户输密码 → Workers 验证（Neon 查加密密码）→ 通过 → 发 token 存 KV
7. 产品图片 URL 是 R2 地址 → 经过 Cloudflare Images 压缩 → 返回给客户
8. 客户看到产品列表，整个过程 1-3 秒

每一步在全球最近的 Cloudflare 节点完成，不需要回源到某个固定服务器。
```
